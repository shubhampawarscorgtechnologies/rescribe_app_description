In practice

A typical day, in order

The same features, arranged the way a doctor actually meets them. This sequence is what a demo or a training session should follow.

  1. Open the app and set the branchMain screen — select branch, read the dashboard.
  2. Ward roundAdmitted Patient card → patient → Facesheet for history, Vitals to record, Orders to prescribe.
  3. Write at the bedsidePen Mode — handwrite on the document instead of on paper.
  4. Start the consulting sessionToday's Appointment — work down the list, update status as each patient is seen.
  5. See online patientsVideo or audio call from the same list; message if a call is not needed.
  6. Look up anyone not on the listSearch → Patient List, then Visit History or Investigation History.
  7. Finish yesterday's paperworkSearch → Visit List → the visit → Pen Mode.
  8. Close the dayMenu — confirm no pending offline data, then log out.

2.6 Medication

A direct medication list for the patient, reachable from the bed without going through the full Facesheet — for a quick "what is this patient on" check during a round.

2.7 Pen Mode

Paperless documentation. The nurse writes or annotates directly on a document with a stylus or finger, the way they would on a paper chart, and the app stores it against the patient's visit. Replaces scanning handwritten sheets back into the record.

  • Handwriting on forms — annotate the document exactly where the pen would go on paper.
  • Saved to the visit — the marked-up document is stored with the patient, viewable later.
  • Works offline — writing done without network is queued and uploaded when the device reconnects.

Behaviour

Working without network

Wards have dead spots. The app is built so a nurse can keep working through them.

  • Reading: ward board, bed lists and previously opened patient data stay viewable from the device's stored copy.
  • Writing: entries made offline are saved on the device and placed in a sync queue.
  • Recovering: when the device is back on network, queued items upload. The Menu screen shows anything still waiting.
  • The one risk: clearing cache or logging out while items are still pending. That is why the pending list exists and why it is checked first.

A typical shift, in order

The same features, arranged the way a nurse actually meets them. This sequence is what a demo or a training session should follow.

  1. Log in and set contextMain screen — select branch, then building, floor and ward.
  2. Read the wardBed Display — count dashboard first, then filter to Today's Admitted and Pending Check-In to find what changed.
  3. Round the patientsOpen a bed → Facesheet → record vitals on the Vital Sheet, log fluids in the Intake/Output chart.
  4. Action clinical ordersFacesheet → Orders — raise Medicine, Lab or Radiology orders; move existing orders forward as they are completed.
  5. Capture services and consumablesOrders — post nursing service orders and the consumables used, so nothing goes unbilled.
  6. Document by hand where neededPen Mode — write on the form directly instead of on paper.
  7. Keep the board trueChange Bed Status — discharges, transfers, handover, so the next shift and the admissions desk see reality.
  8. Close the shiftMenu — confirm no pending offline data, then log out.

What this replaces

Hospitals run on printed forms — consent sheets, nursing notes, treatment charts, referral slips. Traditionally these are filled by hand, then scanned back in, or never digitised at all. Paperless Documentation keeps the handwriting and removes the paper: the form opens on the device, the clinician writes on it with a stylus or finger, and the finished page is stored against the patient's visit.

STEP 1 Document list Documents grouped by category and sub-category. Select, print, email or send on WhatsApp. STEP 2 History screen Everything filed under a sub-category. Upload, create new, edit or view earlier documents. STEP 3 Preview screen Page-level control before it goes out — edit, delete, refresh, print, activity logs. STEP 4 Canvas screen The writing surface. Pen, eraser, highlighter, shapes, overlays, stamps, copy tools.

Where it opens from. Doctor app: Admitted Patients List → patient → Pen Mode, and Search → Visit List → a visit → Pen Mode (for patients seen earlier). Nurse app: the bed on the Bed Display screen → Pen Mode. The screens after that point are identical in both apps.

Step 1

Document list

All documents for the patient, grouped by category and then sub-category. Grouping, display order and colour coding are managed per hospital, so each site sees its own paperwork organised its own way.

ElementWhat it doesWhy it matters
CategoryThe top grouping of documents.Keeps a long list navigable.
Sub-categoryThe specific document type inside a category.This is what opens the History screen.
Sequence orderThe order categories and sub-categories appear in.Puts the most-used forms at the top for that hospital.
ColoursColour assigned to a category or sub-category.Fast visual identification during a busy round.
View all documentsShows everything on the patient in one list.When you don't know which category it was filed under.
Select documentsMulti-select, then output the selection.Sending a set of forms together rather than one at a time.

Sharing a selection

Print PDFProduces a PDF of the selected documents for printing or filing.
Send over emailEmails the selected documents out of the app.
Send over WhatsAppShares the selected documents through WhatsApp.

Patient data leaves the hospital at this point. Email and WhatsApp send clinical documents to an outside service. Whoever operates the app is responsible for sending to the right recipient, and hospitals should confirm this matches their own data-sharing policy before enabling it for staff.

4.6 Overlays placed on the page

Items dropped onto the document itself. Between them they cover the three things handwriting alone cannot do: prove identity, prove provenance, and carry an image.

Camera photoPlaces a photo taken on the spot onto the page.
Camera with geoPhoto plus the location it was taken at.
UHID barcodeThe patient's permanent hospital ID as a scannable barcode.
Visit ID barcodeBarcode identifying this specific visit or admission.
QR codeScannable code carrying the document's reference.
Patient imageThe patient's photo on the document.
Patient infoIdentity and admission details printed onto the page.
Doctor stampsThe doctor's stamp, in place of a physical rubber stamp.

Why barcodes matter: a printed page with a UHID and visit-ID barcode can be scanned back into the system without anyone typing a number. Keep barcodes clear of handwriting — anything drawn across a barcode or QR code can stop it scanning.

In practice

The three flows worth demonstrating

Almost everything staff do with this feature is one of these three. A training session should walk each one end to end.

Flow A — Write a new document at the bedside

  1. Open Pen ModeDoctor: admitted patient → Pen Mode. Nurse: bed → Pen Mode.
  2. Pick the paperworkDocument list → category → sub-category.
  3. Create new documentHistory screen → Create new document. The canvas opens.
  4. Write itPen or finger, eraser and highlighter as needed; add a page if one is not enough.
  5. Stamp and identifyPlace patient info, UHID / visit barcode and the doctor stamp.
  6. Check and closePreview screen — read the pages, then print or leave it filed against the visit.

Flow B — Continue yesterday's chart

  1. Reopen the documentHistory screen → Edit previous document.
  2. Carry the layout overCopy & paste complete page, or copy only the selected block that repeats.
  3. Add today's entriesWrite on the new page; keep the reference panel open for the earlier document.
  4. Correct safelyUndo for a slip; Revert to last saved if the page needs to go back to how it was.

Flow C — Send documents out

  1. Select what goesDocument list → select the documents required.
  2. Choose the routePrint PDF for the file, email or WhatsApp for the recipient.
  3. Confirm the recipientClinical documents leaving the hospital cannot be recalled — check the address or number before sending.
Behaviour

Working without network

Wards and clinic rooms have dead spots, and documentation cannot wait for signal.

  • Writing: pages written offline are saved on the device and placed in a sync queue.
  • Recovering: when the device is back on network, queued documents upload on their own.
  • Checking: the Menu screen in both apps lists anything still pending under View Sync Pending Offline Data.
  • The one risk: clearing cache or logging out while documents are still pending. Check the pending list first.
